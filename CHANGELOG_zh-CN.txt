v1.5.1.48（修复：物品栏无法全选；收藏物品不能再转进搜寻容器）

修复一：随身容器的「物品栏」无法全选
- 日志实证：物品栏每次都是 `gmsState=0 paneSelected=1`，于是每次都走「清空」分支，从来没有执行过全选；而「背包」是 `paneSelected=0`，全选正常。
- 根因：原版 `pane.selected` 在角色物品栏里会残留一条条目（日志里固定是第 3 行，也就是「已装备物品」那个分组行），容器不重绘时没有任何东西会清掉它。上一版把它也算作「已有选中」，结果每次按键都只是清掉这条看不见的残留。
- 修复：`paneHasSelection` 只认本模组自己的多选状态（`gmsSelectionState`），不再参考原版 `pane.selected`。原版单选高亮只是「当前焦点行」，不算多选，不应该阻塞全选。

修复二：收藏物品可以被长按X转进搜寻容器（单人模式）
- 日志实证：`transfer candidate: name=工业染料 favorite=true transferable=true` + `target=crate multiplayer=false` —— 单人模式下收藏物品确实被转进了板条箱。
- 根因：收藏保护被 `isMultiplayerSession()` 包住，单人模式整段跳过。
- 修复：改为无条件生效——收藏物品只能在角色随身容器之间移动，不能进入搜寻/世界容器或地面。联机行为不变。

说明文字
- `全选 / 清除选择按键` 的 tooltip 改为「已经用本模组选中过物品时…」，中英文同步。
- 本版仍保留 `multiSelect` / `xTransfer` 日志，便于再验证一轮。

v1.5.1.45（多选全选键改为「有选中就取消」）

- `全选 / 清除选择按键`（默认 L3+R3）改为严格的二段式开关：
  - 列表里只要有任何物品处于选中状态（多选、单选、鼠标点选都算），按下会先取消全部选中。

v1.5.1.38（修复 clearCache 重置朝向导致方向回退）

修复：手柄转到目标方向后按 A 仍变回原方向（第五层）
- v1.5.1.37 让 `objectIndex` 与 `cursorFacing` 同步，实测日志确认第一次 `create` 已正确（`objIdx` 会跟着光标变成 1/2/3/4），但第二次 `create` 的 `objIdx` 又回到 3。
- 原因：`ISMoveableCursor:clearCache()` 里有一句
  `if ISMoveableCursor.mode[self.player] == "rotate" then self.objectIndex = -1; end`
  而 `ISMoveablesAction:perform()` 每次动作完成都会调用 `clearCacheForAllPlayers()`。于是第一次旋转一完成，`objectIndex` 就被重置为 `-1`；第二次 `create` 时 `isValid()` 用 `objectIndex < 1` 分支重新取 `getFaceIndex()`，拿到的又是家具**原始朝向**（3 = S）。
- 因为 `objectIndex` 会被原版主动清掉，**不能把它当作方向的存储位置**。
- 修复：改用模组自有字段保存玩家选择：
  - 旋转成功时记录 `_gqsFacing`（朝向索引）与 `_gqsFacingObj`（目标对象引用）；
  - 第一次 `create` 执行后置 `_gqsPendingRestore`；
  - 后续重复 `create` 若发现 `cursorFacing` 已被清空、且目标仍是同一件家具，就把 `_gqsFacing` 重新写回 `cursorFacing` 与 `objectIndex`。
- 对象引用校验保证换到别的家具后不会误用旧方向；`_gqsPendingRestore` 保证「进入旋转模式后不转直接按 A」不会被上一次的选择污染。
- 配合 v1.5.1.35 的 `ISMoveablesAction.new` 包装，即使第二次 `create` 时 `currentMoveProps` 仍是旧朝向，动作层也会用正确的方向执行。
- 未修改任何原版文件；全部为运行时方法包装。

验证说明

v1.5.1.37（修复确认键重复执行导致方向被回退）

修复：手柄转到目标方向后按 A 仍变回原方向（第四层）
- v1.5.1.36 已成功屏蔽鼠标指针改写朝向，实测日志出现 `mouse rotate ignored (joypad active), keeping N`，说明那一层已修好。
- 新日志暴露出真正致命的一环：**一次按 A，`ISMoveableCursor:create()` 会被调用两次**：
  ```
  confirm cursor= 1  objIdx= 3  facing= N   ← 第一次，方向正确
  confirm cursor= nil objIdx= 3  facing= S   ← 第二次，方向回退成原朝向
  ```
- 原因：原版 `create()` 在结尾会把 `cursorFacing` 和 `joypadFacing` 都清空：
  `self.cursorFacing = nil; self.joypadFacing = nil;`
  第二次调用时 `cursorFacing` 已是 `nil`，`isValid()` 里的 `local faceIndex = self.cursorFacing or self.objectIndex` 就回退到 `objectIndex`——而这个值仍是家具**原始朝向**的索引（3 = S）。于是第二次执行把第一次转好的方向又转了回去。
- 为什么第一次能对、第二次会错：两版修复都只写了 `cursorFacing`，没有同步 `objectIndex`。原版自己的手柄旋转路径（`rotateKey`）恰恰是靠 `objectIndex = objectIndex + 1` 来推进朝向的，`cursorFacing` 只是鼠标路径的补充。
- 修复：手柄旋转成功时**同时写入 `objectIndex`**（仅 `rotate` 模式，此时它表示朝向索引 1~4；`place`/`pickup` 等模式该字段表示对象索引，不动）。这样即使 `cursorFacing` 被清空，回退值也是玩家选的方向，两次 `create` 结果一致。

v1.5.1.36（修复鼠标位置覆盖手柄旋转方向）

- 前两版（v1.5.1.34 / v1.5.1.35）分别处理了「光标停在顶替朝向」和「反查贴图名失败」，但实测日志显示确认时光标索引总是被改写成 `3`（S），说明方向在按 A 的瞬间被**第三方**覆盖了。

  `if playerObj:isBuildButtonDown() then draggingItem:rotateMouse(x, y) end`

- 修复：包装 `ISMoveableCursor.rotateMouse`，**手柄操作期间直接忽略鼠标旋转**，不改写 `cursorFacing`；鼠标操作时保持原有行为（含同轴吸附）。
- 判定方式双重保险：
  - 手柄最近 4 秒内旋转过方向 → 判定为手柄操作；

v1.5.1.34（修复家具旋转「转了又变回原方向」）

修复：家具旋转后按 A 仍回到原方向

- 新增 GQS_FixScrollingListBoxJoypadB.lua，在不修改游戏原版文件的情况下，为 ISScrollingListBox:onJoypadDown() 加入方法存在性检查，并对 getter 调用增加 pcall 保护。
- 保留原版 A 键双击/覆盖回调、B 键焦点返回、常规按键转发逻辑；仅在父级无法安全确认焦点时跳过那一步可选检查。
